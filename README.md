# QA Resource Portal

Веб-портал управления ресурсами QA-команды: занятость тестировщиков, навыки, потребности (заявки менеджеров проектов) и реестры навыков, проектов и менеджеров.

## Стек

- **Backend:** Node.js + Express 4 (REST API + раздача статики).
- **Хранилище:** один JSON-файл `data.json` на сервере (без СУБД); чтение/запись на каждый запрос, мутации сериализованы очередью.
- **Frontend:** vanilla JS (без сборки) + HTML5 + CSS; Gantt на завендоренной `frappe-gantt`, даты через нативный `Intl.DateTimeFormat('ru-RU')`.

## Возможности

- Дашборд занятости тестировщиков с фильтрами (грейд, проект, статус, период) и проверкой перегрузки (>100%).
- Карточка сотрудника: профиль (ФИО, грейд, email, возраст, «о себе»), навыки с уровнями 1–4, календарь занятости (Gantt) и назначения.
- Заявки на ресурсы («Потребности»): создание, статусы, назначение тестировщика.
  В форме «Новая потребность» и в карточке сотрудника поле «Проект» —
  поисковый выпадающий список по реестру (как в Реестре проектов).
- Тестировщики: при создании («Новый тестировщик») строка «ФИО» ищет по Jira
  (подтягивает ФИО и email); если человек уже есть в реестре — не создаётся дубль,
  открывается его карточка; при отсутствии в Jira можно ввести имя вручную.
  Признак **Outstaff** (вне штата) задаётся чекбоксом — как в форме создания, так
  и в блоке «Профиль» карточки; у сотрудников-аутстафферов рядом с именем (в
  таблице ресурсов и в заголовке карточки) отображается жёлтый треугольник с
  подсказкой «Сотрудник вне штата».
- Реестр навыков (24 навыка, 4 категории, описания уровней).
- Реестр проектов (гос. контракты) и реестр менеджеров.
- **Оценка сотрудников**: импорт JSON-самооценок из MySkills, история оценок
  (по датам, в таблице — последняя), правка уровня/комментария лида в карточке,
  жёлтая подсветка расхождений «самооценка vs лид», экспорт всего в JSON/CSV и
  карточки сотрудника в JSON/HTML.
- Валидация процентов (1–100%), обязательность полей, блокировка удаления используемых проектов/менеджеров.
- Интеграция с Jira (read-only): связывание проектов портала с Jira, загрузка задач с метриками и таблицей задач.

## Структура

```
server.js           HTTP-сервер, REST API, миграции на старте
jira.js             модуль интеграции с Jira (REST API v2, read-only)
seed.js             стартовые данные реестра навыков/категорий
data.json           данные (создаётся при запуске, если отсутствует)
.jira-config.json   настройки Jira (url + токен, НЕ коммитится)
public/             фронтенд (index.html, styles.css, app.js, vendor/)
package.json        зависимости и скрипты
```

## Интеграция с Jira

Портал умеет подтягивать задачи из Jira (Server/DC, REST API v2). Используется
личный токен доступа (PAT) — подключение **только на чтение**, токен не
возвращается на фронт и не хранится в репозитории.

### Настройка

Укажите параметры через переменные окружения или файл `.jira-config.json` в корне
проекта (рядом с `portal.exe` при сборке):

```json
{
  "url": "https://jira.example.ru",
  "token": "JIRA_PERSONAL_TOKEN"
}
```

Либо переменные окружения:

```bash
JIRA_URL=https://jira.example.ru
JIRA_PERSONAL_TOKEN=...
```

### Связывание проектов

**Реестр проектов → «Добавить проект».** Поле «Название проекта» — выпадающий
список проектов Jira: при выборе сохраняется его ключ (`jiraKey`) на проекте
портала. Есть режим «ввести вручную» — произвольное имя без связи с Jira.

### Вкладка «Jira»

- **Проект (мультиселект)** — выпадающий список с чекбоксами и **поиском по
  мере ввода** (ключ или название). Можно выбрать несколько проектов.
- **Исполнитель (мультиселект)** — выпадающий список с чекбоксами и **поиском по
  имени/email**; содержимое зависит от выбранных проектов: участники/исполнители
  этих проектов из Jira (эндпоинт `/api/jira/assignables`) + тестировщики из
  реестра портала (дедуп по email). Пока проект не выбран — список пуст с подсказкой.
- **Избранное (звёзды)** в списках «Проект» и «Исполнитель»: у каждой строки
  справа есть звёздочка. Клик по ней закрепляет запись вверху отдельным блоком
  **«Избранное»** (виден даже при активном поиске; ниже — блок «Все» с остальными
  подсказками/результатами). Повторный клик убирает из избранного. Хранится в
  `localStorage` браузера (per-устройство): проекты — по ключу, исполнители — по
  стабильному идентификатору (accountId/email/ключ).
- Последовательность: сначала выбирается **проект**, затем — **исполнитель(и)**
  из этого проекта. «Загрузить задачи» грузит задачи по выбранным проектам
  и/или исполнителям. Выбор исполнителей **запоминается** при добавлении/снятии
  проектов (не сбрасывается).
- **Дашборд** — сводный блок «По исполнителям» (чипы «ФИО: кол-во») и для каждого
  выбранного исполнителя карточка «По статусам» со строками «Статус: N»
  (например «Закрыто: 14», «Тестирование: 5»). Считается **только по текущему
  (активному) спринту** выбранных проектов и по выбранным исполнителям
  (типы «Задача»/«Ошибка»/«Подзадача»/«Активность»).
- Кнопка **«Сбросить»** рядом с «Обновить» — полностью очищает выбор проектов,
  исполнителей, поисковые поля, локальные фильтры и загруженные результаты.
- Фильтры таблицы **Проект**, **Статус** и **Приоритет** (опция «Все») сужают
  лишь строки списка задач, на дашборд не влияют.
- Столбец **«Спринт»** — активный спринт проекта (резолвится через JQL
  `sprint in openSprints()`, поле спринта определяется автоматически).
- Баннер-предупреждение справа сверху: у исполнителя больше 5 задач в любом
  активном статусе (категории «to do» / «in progress»), кроме статуса «Сделать».
- Таблица задач: Проект, Ключ, Тема, Статус, Исполнитель, Приоритет, Спринт и
  сроки, оценка/затрачено. Клик по задаче — детали, описание, комментарии и ссылка «Открыть в Jira».
- Виджет «Загрузка по проектам» в карточке исполнителя:
  **Текущая загрузка** = задачи «в работе» (статусы «Тестирование/Разработка/В
  работе») / Ёмкость × 100%; **Прогнозная загрузка** = задачи в «Сделать» /
  Ёмкость × 100%. Ёмкость задаётся вручную на вкладке (введённое число
  сохраняется в `data.json`); при превышении 100% значение выводится реальным и
  подсвечивается красным, шкала обрезается на 100%. У заголовка виджета — иконка
  `i` с подсказкой о смысле Ёмкости и видов загрузки.

### Эндпоинты

- `GET /api/jira/users[?q=строка]` — активные пользователи Jira; с параметром `q` — серверный поиск по имени/email (используется в «Новом тестировщике»).
- `POST /api/jira/assignables` — `{ "projectKeys": [...] }` → участники/исполнители
  указанных проектов (для мультиселекта исполнителей).
- `POST /api/jira/active-sprints` — `{ "projectKeys": [...] }` → `{ projectKey: "активный спринт" }`.
- `GET /api/jira/capacities` — ёмкости загрузки исполнителей (manual): `{ capacities: [...] }`.
- `PUT /api/jira/capacities` — сохранить ёмкость `{ projectKey, assignee, capacity }`.

### Замечания

- Загрузка ведётся **по каждому выбранному проекту отдельно** (постранично, до
  ~400 задач на проект), поэтому при выборе нескольких проектов данные всех
  проектов подгружаются корректно, даже если один проект сильно доминирует по
  числу задач.
- Отбор задач серверным JQL сужен до **текущего (активного) спринта** и типов
  **«Задача»/«Ошибка»/«Подзадача»/«Активность»**
  (`project = "KEY" AND sprint in openSprints() AND issuetype in ("Задача", "Ошибка", "Подзадача", 10605, "Активность")`),
  поэтому грузится только нужная выборка (обычно десятки, а не сотни задач);
  клиент дополнительно страхует фильтр по спринту и типу. Тип «Подзадача.» с
  точкой на конце (id `10605`, отдельный от «Подзадача») включается в выборку
  по своему id, т.к. JQL не распознаёт его по имени.
- При сборке `portal.exe` токен не вшивается: задайте окружение или положите
  `.jira-config.json` рядом с exe.

## Запуск (разработка)

Требуется **Node.js 18+** (npm идёт вместе с ним).

```bash
npm install
npm start
```

Откройте **http://localhost:3001**.

При первом запуске, если `data.json` отсутствует, он создаётся, а реестр навыков наполняется автоматически.

## Сборка единого исполняемого файла

Проект можно упаковать в один самодостаточный `portal.exe` (Node.js встраивается внутрь — на целевой машине ничего устанавливать не нужно). Сборка — на 64-битной Windows:

```bash
npm install
npm run build:exe
```

После сборки в корне появится `portal.exe`.

### Как пользоваться exe

- Перенесите `portal.exe` в любую папку с правом записи (рабочий стол, отдельная папка).
- Запустите **двойным кликом** — сервер поднимется, браузер откроет портал сам.
- Рядом с `portal.exe` появится `data.json`, где хранятся данные.

Особенности сборки:
- при запуске автоматически выбирается свободный порт (начиная с 3001) и открывается браузер;
- автозапуск браузера можно отключить переменной окружения `PORTAL_NO_OPEN=1`;
- чтобы портал собрался с уже существующими данными, положите рядом с exe текущий `data.json`.

## Оценка сотрудников

Вкладка «Оценка сотрудников»:
- хранит оценки в отдельной коллекции `assessments` в `data.json` (история по датам);
- импортирует файлы-самооценки из MySkills (`POST /api/assessments/import`);
- связывает оценку с сотрудником по ФИО (создаёт пользователя, если его ещё нет);
- при повторном импорте добавляет новую запись (история), в таблице показывается последняя;
- лид редактирует `leadLevel`/`leadComment` (`PUT /api/assessments/:id/skills/:idx`),
  расхождение с самооценкой подсвечивается;
- удаляет запись оценки (`DELETE /api/assessments/:id`), пользователь остаётся в реестре;
- в таблице: грейд, дата последней оценки, число навыков, средний уровень,
  статус «есть/нет оценки» (зелёный/жёлтый бейдж), фильтры по грейду, периоду,
  статусу и поиск по ФИО;
- экспорт: всё в JSON, CSV (таблица с уровнями), карточка в JSON/HTML (самодостаточная страница).

В карточке сотрудника доступны под-вкладки:
- **Профиль** — уровни/комментарии самооценки и лида, правка `leadLevel`/`leadComment` с жёлтой подсветкой расхождений;
- **Сравнение** — два снимка оценок (по умолчанию последние два, даты можно выбрать),
  таблица «самооценка/лид было → стало» с подсветкой изменений;
- **История** — все записи по сотруднику, сгруппированные по навыкам, в хронологии
  (дата, самооценка, лид, «изменение было → стало», комментарий);
- **Прогресс** — самописный SVG-график изменения уровня по датам (синяя линия —
  самооценка, жёлтая — оценка лида), выбранный навык.

### Нерекурсивные имена файлов

Импорт/экспорт не конфликтуют с `data.json`:
- из MySkills: `self-assessment_<ФИО>_<дата>.json`;
- портал: `assessments_export_<мс>.json`, `assessments_<мс>.csv`,
  `assessment_<ФИО>_<дата>.json` / `.html`.

## MySkills (отдельный сервис-опросник)

`myskills/` — автономный опросник самооценки, собирается в **свой** `MySkills.exe`
(отдельный от `portal.exe`). Без БД и авторизации; встроенная копия реестра навыков.

```
myskills/
  server.js               Express на порту 3200+, раздача статики + автозапуск браузера
  sync-skill-registry.js  генерирует public/skills.js из ../data.json (запуск: npm run sync:registry)
  public/                 статика опросника: 3 экрана (приветствие / форма / результат)
  package.json            script build:exe -> MySkills.exe
```

Запуск в разработке:

```bash
cd myskills
npm install
npm start                 # http://localhost:3200
```

Сборка своего exe:

```bash
cd myskills
npm install
npm run build:exe         # создаст MySkills.exe в корне репозитория
```

- `MySkills.exe` автономен: встроенный реестр навыков, не требует `data.json`, пишет только
  выгружаемый файл-самооценку (по запросу пользователя).
- После импорта в Оценку сотрудников навыки сопоставляются с реестром по имени.
- Если в `data.json` изменялся реестр навыков, обновите встроенную копию:
  `cd myskills && npm run sync:registry`.

## Примечания

- Проект — MVP: одна страница (SPA), без ролей и прав доступа.
- Хранилище локальное (один `data.json`). Подходит для локального/офисного использования; для массового сетевого доступа потребуется СУБД.
- `data.json` не коммитится (содержит рабочие данные) — он исключён в `.gitignore`.
